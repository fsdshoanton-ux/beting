# Киберхоккей: статистика и сигналы на ТБ в периоде

Инструмент собирает историю матчей киберхоккея (игроки указаны в скобках:
`Boston Bruins (Kraken)`), считает статистику голов по периодам для каждого
игрока и каждой пары игроков. Затем он оценивает вероятность тотала больше
в конкретном периоде и шлёт сигнал, когда кэф букмекера выше справедливого.

Нужен только Python 3.10+, внешних зависимостей нет.

## Быстрый старт (на демо-данных)

```bash
python -m cyberhockey demo --out data/demo.csv       # синтетика, НЕ реальные матчи
python -m cyberhockey import data/demo.csv
python -m cyberhockey stats --period 2 --line 1.5    # игроки по доле ТБ во 2-м периоде
python -m cyberhockey pairs --period 2 --line 1.5    # пары игроков
python -m cyberhockey estimate Blaze Viper --period 2 --line 2.5 --odds 1.9
python -m cyberhockey estimate Blaze Viper --period 2 --line 2.5 --odds 2.4 --elapsed 0.4 --score 1-0   # live
python -m cyberhockey backtest --period 2 --line 1.5 --odds 1.85
```

## Реальные данные

1. **История из CSV.** Формат описан в `cyberhockey/collectors/csv_import.py`:
   `match_id,league,start_time,team1,team2,periods`, где periods — `2:1;0:0;1:2`.
   Подойдёт любой источник: сайт результатов, свой парсер, ручной ввод.
2. **Live Фонбета:** `python -m cyberhockey watch --league "H2H" --period-minutes 5`.
   Команда раз в N секунд читает live-фид, записывает счёт и кэфы на тоталы
   периодов, а при перевесе шлёт сигнал. Завершённые матчи попадают в базу,
   так что история копится сама.
   ⚠️ Формат фида не проверен на живом API (из среды разработки сайт был
   недоступен). Сверьте поля и id факторов тотала (`TOTAL_FACTORS`)
   в `collectors/fonbet.py` с ответом `events/list` во вкладке Network в DevTools.
   Длину периода (`--period-minutes`) возьмите из правил своей лиги.
3. **Другие конторы (BetBoom и т.д.)** подключаются так же: нужна функция,
   которая возвращает список `LiveMatch`, по образцу `fonbet.parse_feed`.

### Сигналы в Telegram

```bash
export TELEGRAM_BOT_TOKEN=...   # от @BotFather
export TELEGRAM_CHAT_ID=...
python -m cyberhockey watch
python -m cyberhockey report    # статистика выданных сигналов: выиграно/проиграно, ROI
```

## Как считается вероятность

1. Среднее голов в периоде по лиге — база.
2. Множитель для каждого игрока: насколько его матчи в этом периоде результативнее
   среднего по лиге. Пока матчей мало, множитель подтягивается к 1.
3. Ожидаемые голы = база × множитель₁ × множитель₂, с поправкой на личные встречи.
4. P(ТБ) по распределению Пуассона уточняется фактической частотой ТБ у этих игроков.
5. В live считаются только голы, которые ещё могут забить в оставшееся время периода.

Сигнал выдаётся, когда `P × кэф − 1 ≥ 5%`, P ≥ 55% и у каждого игрока
не меньше 15 матчей в выборке. Все пороги меняются флагами `--min-edge`,
`--min-prob` и `--min-games-signal`.

## Важно

- **Сначала бэктест на реальных данных, потом деньги.** Если в `backtest`
  модель не лучше «средней лиги» или ROI отрицательный, сигналы бесполезны.
  Маржа в киберспорте большая, и букмекер сам строит линию по этой же статистике.
- Бэктест с фиксированным кэфом оптимистичен. Честный вариант — с реальными
  кэфами, которые `watch` сохраняет в базу. Они подставляются автоматически.
